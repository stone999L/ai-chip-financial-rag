# 实验结果与错误分析

## 1. 实验数据与运行环境

本项目最终使用 10 家国产算力与智能芯片相关上市公司 2026 年半年度报告作为语料。全量语料共 1,730 页，经正文与表格解析后形成 5,073 个知识块，其中正文块 2,367 个、表格块 2,706 个。

正式检索实验在 GitHub Actions 的 `ubuntu-latest` CPU runner 上完成。向量模型采用 `BAAI/bge-small-zh-v1.5`，向量维度为 512；关键词检索采用 BM25；二者使用 Reciprocal Rank Fusion（RRF）进行混合召回。

本次 `retrieval-build` 从 08:50:38 开始，到 08:57:49 成功结束，总耗时约 7 分 11 秒。其中“Build BM25 and BGE embedding indexes”约耗时 5 分 52 秒，10 道检索题约耗时 10 秒。

此前曾尝试 `Qwen/Qwen3-Embedding-0.6B`。在相同 GitHub CPU 环境、`batch_size=4` 下，前 7 个 batch 平均约 254 秒/批，若按 1,269 批线性估算约需 89.7 小时，因此正式实验改用更适合 CPU 的轻量中文 embedding。该调整不改变“BM25 + 向量检索 + 混合召回”的实验框架。

- BM25：72%
- 向量检索：86%

## 3. 典型成功案例

### Q3：海光 CPU 与 DCU 的应用场景

BM25、向量和混合检索均只召回海光信息。核心证据集中在第 15 页：CPU 面向复杂逻辑计算、多任务调度等通用处理场景，并广泛应用于电信、金融、互联网、教育、交通等行业；DCU 基于 GPGPU 通用并行架构，主要服务科学计算、人工智能、深度学习训练与推理、大模型和大数据处理。

该题说明：当公司名称、产品术语和报告表述都较明确时，普通混合 RAG 能够稳定定位核心证据。

### Q6：芯原 SiPaaS 与标准芯片销售模式

检索结果集中在芯原股份第 15—19 页。证据明确说明，SiPaaS 不以销售自有品牌标准芯片为核心，而是向客户提供芯片定制解决方案和半导体 IP 授权；IP 业务可获得授权费与量产后的特许权使用费，定制业务可覆盖设计、晶圆制造、封装测试与量产管理。

该题说明：商业模式类问题虽然需要语义理解，但只要问题限定单一公司，BM25 与向量检索可以互补并取得稳定效果。

## 4. 典型失败案例

### Q1：数字正确，但口径可能错

Q1 的目标公司寒武纪在向量和混合检索中被命中，但混合 Top-8 没有召回第 7 页“主要会计数据”表，而是召回了第 64 页母公司利润表。寒武纪合并口径 2026 年上半年营业收入为 5,995,573,619.61 元，同比增长 108.13%，这条完整证据存在于第 7 页，但没有进入混合 Top-8。

这说明财报数字题不仅要“找到相似数字”，还要同时控制：

- 公司是否正确；
- 报告期是否正确；
- 合并报表还是母公司报表；
- 本期还是上年同期；
- 单位是否一致。

因此，财务数字题应增加“公司 + 报告期 + 报表口径”的过滤或重排规则。

### Q7：明确写了两家公司，仍漏掉一家公司

问题明确要求比较瑞芯微与全志科技，但混合 Top-8 只覆盖瑞芯微，没有覆盖全志科技。这是固定 Top-K 检索的典型缺陷：结果会被语义更强的一侧占满，无法保证比较对象完整。

更合适的方式是将问题拆成两个子查询：

1. “瑞芯微端侧智能计算布局”
2. “全志科技端侧智能计算布局”

分别检索后再合并证据。

### Q9、Q10：全景题暴露普通 RAG 的结构性不足

Q9 混合检索只覆盖 6/10 家公司，Q10 只覆盖 5/10 家公司。Q10 还召回了龙芯中科第 170 页关联方信息，属于语义相似但任务相关性较弱的噪声。

这说明跨公司全景题不能简单依赖“对整个语料库执行一次 Top-K”。更可靠的方案是先识别问题需要覆盖的公司集合，再按公司逐一检索，最后做证据汇总和去重。这与课程中“问题拆分、Agentic RAG、全景组织”的思路一致。

## 5. 结论

本实验得到三个主要结论。

第一，单公司事实与语义问题适合普通 BM25 + 向量混合 RAG。Q2-Q6 均能稳定召回足够证据，说明轻量 embedding 配合 BM25 已能满足大部分单公司财报问答。

第二，财务数字题必须额外处理口径。Q1 虽然命中寒武纪，却出现“合并报表关键表格未进入 Top-K、母公司报表进入候选”的问题。财报 RAG 的难点并不只是语义相似，而是公司、期间、报表层级、单位和科目的共同约束。

第三，跨公司全景问题需要覆盖感知检索。Q7-Q10 的结果表明，固定 Top-K 无法保证每个目标公司都有证据。后续最优改进方向不是盲目更换更大的 embedding 模型，而是增加公司识别、问题拆分、分公司检索、证据覆盖检查和全景汇总机制。
