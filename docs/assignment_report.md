# 国产算力与智能芯片上市公司财报问答知识库构建
## ——基于向量检索与 BM25 的混合 RAG

> 课程作业 A 草稿。实验结果部分必须在系统真实运行后填写，本文不预先虚构准确率或召回效果。

## 一、研究背景

上市公司半年度报告同时包含管理层讨论、主营业务、核心技术、研发活动、风险因素以及大量财务报表和附注。对于国产算力与智能芯片企业而言，不同公司在 AI 训练与推理芯片、CPU、GPU、端侧 SoC、芯片 IP、FPGA 等技术方向上具有明显差异，仅依靠关键词搜索难以稳定回答同义表达和技术路线问题；而仅依靠向量检索，又可能在公司名称、芯片型号、会计科目、报告期等需要精确匹配的信息上产生误召回。

因此，本项目选取 10 家国产算力与智能芯片相关上市公司，以统一报告期的 2026 年半年度报告为知识来源，构建“BM25 + 向量检索”的混合财报问答知识库。系统要求所有回答尽量回链至具体公司、报告期、章节和页码，并通过 10 道测试题观察单公司问题、双公司比较问题和跨公司全景问题的差异。

## 二、样本与数据范围

样本公司包括：寒武纪、海光信息、龙芯中科、景嘉微、芯原股份、瑞芯微、全志科技、北京君正、国科微、复旦微电。

统一报告期为 2026 年半年度报告。数据源优先使用上海证券交易所、深圳证券交易所公告 PDF；当公开检索稳定返回巨潮资讯的报告全文 PDF 时，仓库会如实标记为 CNINFO 来源，不把巨潮链接伪装成交易所直链。

当前数据来源状态以 `data/reports_manifest.csv` 为准。

## 三、系统设计

### 1. 文档解析

PDF 解析分为正文与表格两条路径。正文按页提取并识别当前章节；表格尽量保留原始行列关系。每页记录包含公司名称、证券代码、报告期、报告标题、页码、章节、正文、表格以及原始文件名。

### 2. 切块与元数据

正文目标块长度约 900 个汉字，相邻块保留约 120 个字符重叠，并优先在句号、问号、感叹号和分号后切分。表格作为独立块保存，避免将表头和关键数值完全分离。

每个块至少保留：

- 公司名称
- 证券代码
- 报告期
- 章节
- 页码
- 内容类型（正文 / 表格）
- chunk_id
- 原始文件名

这样做的目的，是避免财报问答中出现“数字本身正确，但公司、期间或口径错误”的情况。

### 3. BM25 检索

BM25 使用 jieba 分词。其优势主要体现在公司名称、证券代码、产品型号、专业术语以及会计科目等需要字面匹配的信息。

### 4. 向量检索

向量检索默认使用 Qwen3-Embedding-0.6B，将“公司名 + 章节 + 页码 + 正文/表格内容”共同编码。其主要作用是召回同义表达、业务场景和技术路线等语义相近内容。

### 5. 混合召回

BM25 和向量检索分别返回候选块，再使用 Reciprocal Rank Fusion（RRF）按排名进行融合。当前版本故意保持结构简单，以便清楚观察基础混合 RAG 在跨公司全景问题上的能力边界。

### 6. 回答与溯源

回答模型只能依据检索出的证据作答。证据不足时应明确说明“当前检索证据不足，无法确认”，不得自行补充未被召回的财务数字。回答页面同时显示证据块的公司、章节、页码、检索路线和 RRF 分数。

## 四、测试题设计

共设置 10 道测试题：

- Q1-Q6：单公司数字、产品、技术路线和商业模式问题；
- Q7：两家公司比较问题；
- Q8：多公司研发投入变化问题；
- Q9-Q10：跨公司全景题。

其中 Q9、Q10 用于重点观察固定 top-k 是否会遗漏部分公司，以及普通碎块检索能否覆盖“十家公司之间的共同技术路线、风险与应对措施”。

完整测试题见 `evaluation/questions.json`。

## 五、评价方法

本项目不只判断最终答案“看起来是否合理”，还记录检索层证据：

1. 召回了哪些 chunk；
2. 覆盖了哪些公司；
3. 证据是否足以回答问题；
4. 最终回答是否正确；
5. 错误属于哪一类。

计划重点分析以下错误：

- 公司召回错误；
- 本期 / 上期混淆；
- 合并 / 母公司口径混淆；
- 表头与数值被切开；
- 专有名词同义表达导致 BM25 漏召回；
- 向量检索未精确命中型号、公司名或科目；
- 跨公司题 top-k 只覆盖少数公司；
- 证据不足但生成模型仍试图补全答案。
