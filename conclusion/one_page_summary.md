# 一页实验结论

## 研究对象与方法

本项目选取寒武纪、海光信息、龙芯中科、景嘉微、芯原股份、瑞芯微、全志科技、北京君正、国科微、复旦微电 10 家国产算力与智能芯片相关上市公司，以 2026 年半年度报告为统一语料。10 份报告共 1,730 页，经解析后形成 5,073 个知识块，其中正文 2,367 块、表格 2,706 块。

检索系统采用 BM25 + `BAAI/bge-small-zh-v1.5` 向量检索，并通过 RRF 进行混合召回。正式实验在 GitHub Actions CPU 环境真实运行，向量维度 512；建索引约 5 分 52 秒，10 道测试题约 10 秒。

## 主要结果

10 道题平均公司覆盖率为：BM25 72%、向量检索 86%、混合检索 81%。

单公司问题表现明显更稳定。Q2-Q6 均能召回足够证据，说明关键词检索与语义检索在公司、产品、技术和商业模式问题上具有较好的互补性。

Q1 暴露了财务数字题的特殊风险：虽然目标公司被召回，但合并口径营业收入总额未进入混合 Top-8，同时母公司利润表进入候选，说明财务问答必须额外控制“公司—期间—报表口径—单位—科目”。

跨公司问题是普通 RAG 的主要短板。Q7 两公司比较题只覆盖 1/2 家；Q8、Q9、Q10 的混合覆盖分别为 5/10、6/10、5/10。固定 Top-K 会被少数高相关公司占满，相关性高并不等于全景覆盖完整。

## 模型与工程取舍

最初尝试 Qwen3-Embedding-0.6B，但在 GitHub CPU 环境中前 7 个 batch 平均约 254 秒/批，按全量 1,269 批估算约需 89.7 小时，不具备课程作业的可复现性。因此正式实验改用 BGE-small。更换 embedding 后，检索框架、问题集和评价方式保持不变，完整 retrieval workflow 实际约 7 分钟跑完。

这一结果说明：工程上模型并非越大越好。对于课程级财报知识库，模型效果、运行成本与可复现性需要共同考虑。

## 最终结论

本项目验证了“BM25 + 轻量向量检索”对单公司财报问答的有效性，同时也证明了普通 Top-K RAG 在财务口径控制和跨公司全景问题上的明显局限。

下一步最值得改进的不是简单替换更大的 embedding 模型，而是引入公司识别与过滤、问题拆分、按公司独立检索、覆盖率检查以及 Agentic RAG 式的证据组织。这样才能从“找到几个相关片段”进一步提升到“完整覆盖问题要求的所有对象并保持可追溯性”。
